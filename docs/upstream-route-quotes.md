# Read-only upstream route quotes

`GET /api/market/admin/upstreams/:id/route-quotes?model=<optional search>`

Administrator authentication is required. The endpoint returns reference quotes grouped by the base model, with one entry per complete upstream access-model identifier. Search matches base models, access-model identifiers and complete channel IDs such as `ID00013`.

The source must belong to an account with a saved authorized Key-page snapshot. The authorized browser reads `/api/marketplace/pins` with its existing login, separates memberships by `token_id`, and saves each Key's `joined_routes`. Numeric and decimal-string IDs are supported. Listing ID is the required membership identity; base model and alias are optional enrichment and, when supplied, must agree with that exact marketplace listing. Missing enrichment is resolved only through the selected listing ID. Model permissions additionally restrict scope; a base-model permission never grants every merchant route. Membership is not an inference test: `access_verified` remains false. A missing membership read is distinct from a successful empty list.

The reader saves `reader_version` and a bounded per-Key `joined_routes_issue` when membership cannot be read. HTTP failures identify `/api/marketplace/pins` and its status; malformed responses are distinguished from missing reader reporting. An invalid route belonging to another identifiable Key cannot invalidate this Key. Malformed own routes or unassignable Key identities block import, never produce a partial or fabricated selection. Catalog failures remain visible in the connection dialog rather than being treated as successful authorization. Existing saved bookmarks contain their reader code; replace them with the current connection bookmark to pick up reader updates.

The reader makes a credential-free, same-origin GET to the upstream's public `/api/marketplace/listings?sort=price_asc`. It matches the joined listing ID, base model and complete alias before using a quote. It does not guess the cheapest route or merge merchant aliases.

For this merchant schema, CNY purchase prices follow the upstream page: multiply its raw `*_usd` input/output/cache/per-request quotes by the response's explicit positive `fx_rate_cny_per_usd`. Missing or invalid FX blocks price confirmation; no rate is guessed. The page's RMB multiplier is CNY input price divided by the official input face value. Retain those official face values as the page's comparison reference, rather than multiplying the already-discounted purchase price by another discount. All prices use explicit per-million-token or per-request units. Missing prices stay absent and explicit zero stays zero. This website-specific rule does not change ordinary group prices, Key spending or account balances.

If the public marketplace is inaccessible, unsupported or incomplete, the reader uses the saved authorized `/api/pricing` response and marks that origin and its timestamp. A raw `model_ratio` is returned as `input_coefficient`, never as a discount multiplier. The authorization snapshot may be older than ten minutes; `snapshot_stale` makes this explicit without requiring a mutation to inspect saved data.

Successful responses contain `read_only`, `currency`, `source_id`, `snapshot_time`, `snapshot_stale`, `quote_time`, `origin`, `model_count`, `route_count`, `issues` and `models`. Each model contains its distinct `routes`, including `access_model`, `prices`, `original`, optional `multiplier`, and optional upstream channel/supplier identifiers. Credentials and encrypted snapshots are never returned.

This endpoint does not update accounts, Keys, sources, catalog snapshots, revisions, listings or selling prices. It does not run model inference.

Upstream marketplace listing IDs (for example `ID00287`) are different from supplier/channel coordinates (`S1/13`, channel `ID00013`). Save both identifiers; the management list can search either complete padded ID.

## Formal merchant-route catalog

The existing model/price refresh authenticates the saved Key against its actual model endpoint, intersects live model permissions with the authorized Key scope and joined-route memberships, and imports only those complete `base_model@s…c…` aliases. Missing membership snapshots require a fresh authorization using the current bookmark. A successful empty membership list imports zero routes. Each quote retains its listing ID, base model, full channel ID, supplier, CNY display rate, independent official reference and CNY purchase prices.

An authorization that changes route membership invalidates the saved catalog, allowing the existing connection callback to refresh models/prices automatically. Unchanged membership renewals keep the catalog. This never modifies existing selling contracts or listing states.

Fresh public quotes and live model permissions cannot revalidate private route membership. Formal refresh/publication requires that the authorized Key and joined routes were read within ten minutes; the existing browser connection renews its read every four minutes while open. Stale or missing membership requires another authorized read. Public inspection exposes its older snapshot explicitly and never publishes. A joined route that is absent from an otherwise complete public quote list retains its authorized alias as an unavailable management row, without prices. It cannot be published or borrow another route’s price, and does not block valid joined routes. Missing, disabled or expired Keys, duplicate aliases, incomplete public lists and mismatched route identities remain blocked. Ordinary group-based imports retain their authorization workflow.

`realtime_ratio` and even a field named `realtime_ratio_cny` are not substituted for the verified page formula. Procurement and selling contracts use the converted per-dimension purchase prices. Official cache rates absent upstream remain absent and are not inferred by reversing the ratio. Saved pre-fix catalogs without verified CNY metadata cannot be published.

For this marketplace, its public documentation defines long-context thresholds on **uncached input**, inclusive at the threshold. The quoted input/output long-context factors apply to their text dimensions; the separately quoted cache rates remain independent. These rules are frozen in the purchase contract and multiplied only by the administrator's selling markup. The management card displays the original base prices and an explicit tier explanation. The official reference contract uses only the original dimensions actually supplied upstream.

Refresh changes only the catalog and its revision. Publishing still uses selection, preview and explicit application, with each complete access alias sent upstream unchanged. Existing listing prices and enabled/paused states stay unchanged during refresh. Saved unjoined candidates without a local listing are hidden from the management directory, while existing published/paused records remain available for management. Preview rechecks the current authorized memberships, so removed/blocked routes cannot be newly published from an older catalog. The read-only inspection endpoint does not claim inference success for untested routes.
